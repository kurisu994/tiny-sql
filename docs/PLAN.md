# v0.6 开发计划

> 本节为 2026-08-24 起草的草案。V6-CP0（v0.5 用户验收清零 + 需求收口）完成后 Week 1 开工；等待期间只做文档级契约。

**周期与预算**：8 周，约 96-100h，按作者业余时间 12-13h/周。

**定位**：v0.6 的主题是「结构对比、可审阅同步与关系图」。在 v0.5 已能改单库结构之后，让作者对着 prod / staging 两套连接看清差异（FR-220，P0），再生成可审阅的结构同步脚本（FR-261，P1，默认不自动执行），并补上只读 ER（FR-263，P1）。完整范围以 [ROADMAP v0.6](./ROADMAP.md#v06--结构对比可审阅同步与关系图) 与 [REQUIREMENTS §3.6](./REQUIREMENTS.md#36-v06-范围结构对比可审阅同步与关系图) 为准。

**为什么不把原 v0.6+ 整包塞进来**：数据传输、用户权限、BI/AI 各自是另一条产品线。8 周只扛「1 个不降级 P0 + 2 个可降级 P1」。

| ID | 功能 | 优先级 | 版本内地位 |
|---|---|---|---|
| FR-220 | 双连接结构 diff（库 / 表 / 列 / 索引 / 约束） | P0 | 不降级 |
| FR-261 | 由 diff 生成可审阅结构同步 SQL | P1 | 可降级「只生成不执行」；不做数据拷贝 |
| FR-263 | 只读 ER（由已有 FK 元数据） | P1 | 可降级整项 |

## V6.2 时间线与依赖顺序

```text
Phase 0  前置  v0.5 验收清零 + v0.6 需求收口（不计入 8 周）
Week 1  13h  结构快照与差量模型：表/列/索引/约束双方言（FR-220 内核）
Week 2  13h  双连接选择 + 对象列表 diff UI（FR-220 前半）
Week 3  12h  列/索引/约束明细对比 + 导出报告（FR-220 收口）
Week 4  12h  由 diff 生成结构同步 SQL（FR-261 前半）
Week 5  12h  脚本预览确认执行 + 失败定位（FR-261 后半）
Week 6  13h  只读 ER：FK 构图、节点/边、点击定位（FR-263 前半）
Week 7  12h  ER 布局/筛选打磨 + 双方言回归（FR-263 后半）
Week 8  12h  双连接 dogfooding + 文档 + RC / 正式发布

合计约 99h；P0（FR-220）目标 Week 1-3 完成。
```

关键依赖链：

1. 已有 `list_tables` / `list_columns` / `list_indexes` / `list_constraints` + 打开多条连接 → 结构快照。不新开「同步协议」契约，diff 是应用层组合。
2. AppState 已按 connection_id 注册多条 `OpenConnection` → 左右两侧各用一条已打开连接，不隐式重连、不串 session。
3. v0.5 `ddl.ts` ALTER / 索引 SQL → 同步脚本生成复用同一套标识符与白名单；执行走 `db_query` / `db_query_many` 写确认。
4. ER 只读消费 FR-241 外键元数据，不做正向工程、不手动画线落盘。

## V6.3 分周任务与验收

### v0.6 Week 1 — 结构快照与差量（13h）

- **V6-T1.1 [5h]** 快照类型：对单个 `(connection, database, schema?)` 拉取表（仅 BASE TABLE）+ 列 / 索引 / 约束。纯函数 `diffSchemas(left, right)` 产出 added / removed / changed。
- **V6-T1.2 [5h]** 列变更拆成类型 / 可空 / 默认值；索引按列集 + 唯一性；约束按类型 + 列 + 引用文本。标识符比较大小写规则按方言（MySQL 列名不敏感，PG 敏感）。
- **V6-T1.3 [3h]** 单测：空库、只加表、只删列、复合主键、双方言引号。禁止把「仅注释不同」当成必须同步项（注释差异单独标记，默认可忽略）。

验收：差量纯函数可测；**V6-CP1** 通过后进入 Week 2。

### v0.6 Week 2 — 双连接 diff UI（13h）

- **V6-T2.1 [6h]** 新「对比」工作台：左右各选一条**已打开**连接 + database / schema；未打开的连接只提示去打开，不在 diff 里偷偷 `connection_open`。
- **V6-T2.2 [4h]** 表级列表：仅左 / 仅右 / 双方都有但有差异 / 一致（可折叠）。
- **V6-T2.3 [3h]** 加载中与取消：两侧 metadata 并行拉，用各自 connection 的 cancel token；一侧失败不污染另一侧。

验收：作者能对两条已打开连接看出「哪张表只在 staging」。

### v0.6 Week 3 — 明细对比与报告（12h）

- **V6-T3.1 [5h]** 选中表后展示列 / 索引 / 约束左右对照（增删改高亮）。
- **V6-T3.2 [4h]** 导出 Markdown / 纯文本报告（dialog 选路径 + 后端写文件）。
- **V6-T3.3 [3h]** 跨 driver 对比：允许 MySQL vs PG，但结果页明确「方言不同，仅供人工阅读，不能一键同步」。

验收：**V6-CP2** 同方言双连接结构 diff 可用。

### v0.6 Week 4 — 同步 SQL 生成（12h）

- **V6-T4.1 [6h]** 方向固定为「把右侧改成与左侧一致」或反过来，用户选一次方向。只生成结构语句：CREATE / DROP TABLE、列 ALTER、索引 / 约束增删。复用 `ddl.ts`，危险语句独立成条。
- **V6-T4.2 [4h]** 不做：数据 COPY、TRUNCATE、换主键、RENAME（与 v0.5 同一边界）。跨 driver 禁止生成执行脚本。
- **V6-T4.3 [2h]** 单测：加列 / 删索引 / 仅右有表 → DROP（必须标危险）。

验收：同方言 diff 能产出可审阅 SQL 文本。

### v0.6 Week 5 — 预览确认执行（12h）

- **V6-T5.1 [5h]** 确认框展示完整脚本；执行走目标连接的 `db_query_many`（已有写确认）。失败定位语句序号，已执行部分如实报告（DDL 通常不可事务回滚）。
- **V6-T5.2 [4h]** 执行后刷新目标侧快照并重跑 diff。
- **V6-T5.3 [3h]** 可降级：来不及执行就只保留「复制 / 保存 SQL」。

验收：**V6-CP3** 至少「生成 + 保存脚本」可用；能执行则更好。

### v0.6 Week 6 — 只读 ER（13h）

- **V6-T6.1 [6h]** 当前 database/schema 下用 FK 约束画表节点与边；无 FK 的表仍列出。
- **V6-T6.2 [4h]** 点击节点打开已有结构页；点击边高亮引用列。
- **V6-T6.3 [3h]** 布局用简单分层 / 力导向其一，不引入重型图编辑器依赖。

验收：有外键的库能看出谁引用谁。

### v0.6 Week 7 — ER 打磨与双方言（12h）

- **V6-T7.1 [5h]** 按表名筛选、隐藏无关系表、缩放/平移。
- **V6-T7.2 [4h]** MySQL / PG 双方言 FK 文本解析足够画出边；画不出的约束降级为节点上的文字。
- **V6-T7.3 [3h]** 不做正向生成 DDL、不持久化用户拖拽坐标（本版）。

验收：**V6-CP4** 只读 ER 双方言可用，或按降级整项移出。

### v0.6 Week 8 — dogfooding 与发布（12h）

- **V6-T8.1 [4h]** 双连接 × 直连 / 1 跳：diff、生成脚本、（可选）在测试库执行、ER。
- **V6-T8.2 [3h]** RC ≥ 1 周：0 误执行生产破坏性脚本、0 凭据泄露、0 不可恢复 crash。
- **V6-T8.3 [3h]** REQUIREMENTS §3.6 收口、ARCHITECTURE 补 diff/同步/ER、RELEASE_CHECKLIST v0.6、CHANGELOG。
- **V6-T8.4 [2h]** `just check` + 针对性单测。

验收：**V6-CP5** 发布门槛通过。

范围超时时按以下顺序降级：FR-263 整项 → 同步脚本「只生成不执行」→ 跨 driver 对比（保同方言）→ 报告导出。**FR-220 同方言结构 diff 不降级**。

## V6.5 测试矩阵

- **diff 矩阵**：仅左 / 仅右 / 列类型变更 / 默认值 / 索引列序 / 复合主键；MySQL 与 PG 各自一对连接。
- **同步矩阵**：生成 SQL 与手工预期一致；跨 driver 拒绝生成；执行失败定位；确认框含完整文本。
- **ER 矩阵**：无 FK 库不崩；自引用；复合外键；点击定位。

## V6.6 主要风险

| 风险 ID | 描述 | 影响 | 缓解 |
|---|---|---|---|
| V6-R01 | 误把 staging 脚本打到生产 | 高 | 确认框写明目标连接名 + 完整 SQL；默认不自动执行 |
| V6-R02 | 两边元数据快照时间差造成假差异 | 中 | 每次对比重新拉；界面显示快照时间 |
| V6-R03 | MySQL vs PG 类型无法机械对齐 | 高 | 跨 driver 只展示不生成脚本 |
| V6-R04 | DDL 执行无法整体回滚 | 高 | 失败如实报告已执行序号；引导用官方备份 |
| V6-R05 | ER 大库卡死 | 中 | 先做当前 schema；超过阈值提示筛选 |
| V6-R06 | 数据同步 / 权限 / AI 范围膨胀 | 中 | 明确不做；Week 7 后不加新 FR |

明确不进入 v0.6：数据传输 / 行级同步、用户权限（FR-262）、BI / AI、自动执行无预览的破坏性变更、跨 driver 一键同步、应用内账号。

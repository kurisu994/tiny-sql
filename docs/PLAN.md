# v0.8 开发计划

> 本节为 2026-08-24 起草。功能开工建议等 v0.4–v0.7 用户验收清零；等待期间只改文档契约。

**周期与预算**：8 周，约 96–100h。

**定位**：v0.8 的主题是「防连错与查询补齐」。v0.4–v0.7 已经能改表、搬数据、看计划；日常更大的风险是**连上生产还点了写**，以及格子里看不清值、不能顺着外键跳。本版先把连接级只读和环境色做实，再补同库「复制为新表」、单元格检查器 / FK 跳转；时间允许再收 RENAME COLUMN 与 EXPLAIN 提示。完整范围以 [ROADMAP v0.8](./ROADMAP.md#v08--防连错与查询补齐草案) 与 [REQUIREMENTS §3.8](./REQUIREMENTS.md#38-v08-范围防连错与查询补齐) 为准。

**为什么不把双向同步 / BI / AI 塞进来**：各自是另一条产品线，和跳板叙事无关，8 周业余扛不住。它们挂 **v0.9+**。

| ID | 功能 | 优先级 | 版本内地位 |
|---|---|---|---|
| FR-270 | 连接只读开关 | P0 | **不降级** |
| FR-271 | 连接环境色 / 标签 | P1 | 可降级为仅文字标签 |
| FR-272 | 同库复制为新表 | P1 | 可降级 |
| FR-273 | 单元格检查器 + 外键跳转 | P1 | 可降级为只检查器 |
| FR-274 | RENAME COLUMN 预览 | P1 | 可整项降级 |
| FR-275 | EXPLAIN 读后提示 | P1 | 可整项降级 |

业余 8 周仍只保证 **1 个不降级 P0**。上表后五项按降级链砍，不把「六项全做完」写成承诺。

## V8.2 时间线

```text
Week 1  13h  只读开关内核：落盘字段 + 后端写路径拒绝（FR-270）
Week 2  13h  只读 UI：表单 / 工作台横幅 / 写入口禁用（FR-270）
Week 3  12h  环境色：列表、标题、确认框、拷贝/备份（FR-271）
Week 4  12h  复制为新表：预览 CREATE + 可选灌数（FR-272）
Week 5  12h  单元格检查器（FR-273 前半）
Week 6  13h  外键跳转到被引用行（FR-273 后半）
Week 7  12h  RENAME COLUMN + EXPLAIN 提示（FR-274 / FR-275）
Week 8  12h  dogfood + 文档 + RC
```

关键依赖：

1. 只读是**应用层**开关，不替代数据库账号权限；后端所有写 command 都要认，不能只藏按钮。
2. 环境色只做视觉与确认文案，不改变 SSH / 鉴权。
3. 「复制为新表」默认同连接、同方言；目标表名必须手输；先预览建表 SQL，再可选走现有拷贝内核。
4. 外键跳转只用已有 `list_constraints` + `browse_table` 筛选，不新开同步协议。
5. RENAME 仍走 `ddl.ts` 预览 + `db_query` 写确认；不承诺换主键。
6. EXPLAIN 提示只标注危险节点，不改写 SQL、不做监控采集。

## V8.5 风险

| ID | 风险 | 缓解 |
|---|---|---|
| V8-R01 | 只藏按钮、后端仍能写 | 所有写 command 认 `readOnly` |
| V8-R02 | 只读被理解成数据库账号只读 | 文案写明是应用开关 |
| V8-R03 | prod 色不够显眼 | 确认框重复标签；不做自动只读 |
| V8-R04 | `CREATE TABLE LIKE` 丢索引/外键预期 | 预览里写清 MySQL LIKE / PG 重建范围 |
| V8-R05 | FK 跳转连错库 | 仅当前连接、当前库 |

明确不进入 v0.8：双向行级同步、冲突合并、BI 仪表板、AI、应用内账号、按环境自动只读、跨连接 FK。
